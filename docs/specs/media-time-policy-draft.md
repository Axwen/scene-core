# 素材时间规则

状态：用户已确认，作为候选 Protocol 0.1 的规范性补充；保留原文件路径以避免链接失效。规则已确定；Phase 0 纯转换与 DTO 校验已在 `crates/scene-core-protocol` 实现（`tests/media_time_contract.rs` 通过，共 110 个用例），fixture、Schema 和真实媒体验证尚未完成。

## 目的与边界

让标注、帧、后续音频/ASR 和播放器定位共享一个坐标系。公共请求和标注使用素材毫秒时间；内部保留有符号有理时间，不能通过浮点累计或帧号/平均帧率推算展示时间。

## 1. 时间原点

采用固定工具链解复用后、已应用容器编辑列表等展示语义的容器 presentation start 作为唯一原点 O。不能直接使用未处理的文件原始 ticks；不能按所选音轨/视频轨改变原点，也不能将每条轨道分别归零。

首版仅在该原点可可靠取得时提供可信时间定位。原点缺失或时间体系矛盾时，probe 可以返回其他元数据，归一化位置为 null；不以第一张抽样帧、最早已读取包或默认零猜测原点，不为了 probe 全量解码寻找起点。后续可根据真实样本单独增加确定性 fallback。

播放器不保证天然采用同一原点。Seek Host 必须通过样本验证或适配换算将素材时间映射到播放器时间，不能直接假定 currentTime 与 Core 时间相同。

## 2. 转换与字段语义

```text
展示时间 P = presentation timestamp × time_base
素材时间 T = P - O
公共毫秒值 = 对 T × 1000 执行指定舍入
```

O、P 和差值在舍入前保持有理数，使用检查溢出的整数运算。不使用 DTS（解码顺序时间）定位展示帧。若引擎不能证明处理后的 P 与 O 同域，不输出可信时间。

未发布 0.1 采用：container.startTimeMs 在原点有效时为 0，否则 null；stream.startTimeMs 为相对 O 的有符号整数或 null。负轨道起点可以表达预滚或早于容器原点的内容，不能裁成 0；负位置不开放为公共用户请求/标注。

这明确修改当前 Spec 中“start 非负”的规则。实际展示产物只定位素材时间 >= 0 的内容。durationMs 是长度，不是结束位置；轨道结束点由已知 start + duration 求得，未知值不参与推导。容器 duration 使用同一工具链的容器展示跨度定义，不以最长轨道 duration 直接替代。

## 3. 舍入与区间

- 点时间、元数据起点和 duration：舍入到最近整数毫秒，恰好半毫秒时远离零，例如 1.5→2、-1.5→-2。
- 从精确时间生成覆盖区间：起点向下取整，终点向上取整；区间为 [startMs,endMs)，不得为相邻段强制去除舍入产生的重叠。
- 已经是整数毫秒的调用方请求保持原值；范围必须 start >= 0 且 end > start。
- 先以精确有理时间判断负值/越界，再舍入；避免 -0.4ms 被舍成 0 后误认为合法产物。
- 不把毫秒精度宣传成帧精度；帧选择误差、ASR 误差和毫秒舍入误差分别报告和验证。

## 4. 抽帧与未知时间

requestedTimeMs 表示意图，presentationTimeMs 表示实际选中帧。两者不要求相等；现有诊断预览允许实际时间 null，但 Host 不得用请求时间替代它作为出镜证据。

后续分析抽帧首版建议定义为“目标时刻或之后的第一张有效展示帧”，按精确展示时间选择，不能把关键帧快速 seek 的落点视为结果。末尾无后继帧时明确返回未找到，不偷偷选择前帧。这是未来操作的约束，不改写当前诊断预览 profile。

可变帧率是正常输入，按实际展示时间定位；B 帧的解码顺序不同也不是时间异常。时间戳复位、无法解释的展示回退或映射不唯一属于不可靠时间轴。

## 5. 后续音频映射

音频操作由 Core 实现，当前不添加输出字段。其未来 Spec 必须记录实际第一输出样本对应的素材时间、输出采样率和有效样本数，并处理编码延迟、预滚与重采样延迟。

仅当连续、未变速且映射被验证时：素材时间 = 实际音频起点 + 样本序号 / 输出采样率。ASR 的局部秒数在该映射上换算；不能仅用请求裁剪起点相加。

例如请求从 60s 提取，但实际第一样本对应 60.020s，ASR 局部 5s 对应素材 65.020s。不同音视频轨的相对偏移必须保留。

首个音频版本不做静默去空白、拼接、变速或不连续时间修复；发现无法保持单一连续映射的输入则显式拒绝该操作。多段映射仅在真实需求出现时立项。

## 6. 异常与资源策略

probe 中不可确定的位置为 null，不因一个未知字段而丢弃所有可用元数据。诊断预览可以保留无可信时间的图像；需要精确时间的后续操作遇到不可靠时间轴则受控失败，不发布可定位结果。

已有 0.1 无专用时间错误码，建议使用 UNSUPPORTED_INPUT 表达无法满足操作时间契约，提供安全 cause/nextStep；真正解析损坏仍用 CORRUPT_MEDIA。不扩大自由错误 details。整数越界显式处理，不 wrap、不 NaN、不伪造时长。

probe 不通过全文件扫描保证时间连续；其输出不是整片可定位证明。执行媒体操作时继续检查实际覆盖范围，发现矛盾即使 probe 曾成功也可以失败。取消、超时和磁盘不足沿用已有终态/不可发布规则。

## 7. 验收样本与测试

| 用例 | 预期 |
|---|---|
| O=10s，视频起点10s、音频10.08s | 视频0ms、音频80ms，不分别归零 |
| O=-2s，展示帧P=-1.5s | 帧500ms，负原始时间正常转换 |
| O=0，轨起点=-80ms | stream.startTimeMs=-80；公共负请求被拒绝 |
| 原点缺失 | 元数据位置null，不猜0、不全量扫描 |
| 有理点时间±1.5ms | 分别为2ms、-2ms |
| 精确区间[1.2,1.8)ms | 覆盖区间[1,2)ms |
| VFR、B帧 | 依据展示时间；解码乱序不误报回退 |
| 素材尾部没有目标后继帧 | 后续分析抽帧明确未找到 |
| 请求60s、实际60.020s、ASR局部5s | 回映65.020s |
| 时间复位、音频不连续 | 精确操作受控失败，不造连续映射 |
| 编辑列表、编码延迟、不同播放器原点 | Core与Seek对齐已知声画事件，差异可解释 |
| 极大ticks/时长 | 溢出受控，不wrap或崩溃 |

## 对现有计划的影响

主 Spec 与 SC-P0-02/03 引用本规则，实现时须验证有符号起点、公共时间语义及正反 fixture。无需提前实现音频、创建分析服务、改动人物数据模型或调整已批准的首版范围。

## 决策记录

用户已整体批准：容器展示原点、允许有符号轨道起点、未知不猜、精确操作遇不可靠时间映射时拒绝。主要取舍是部分异常素材暂时无法精确定位；收益是避免无提示地把字幕与人物标注定位到错误画面。未来音频/分析抽帧的专用字段仍由各自 Spec 定义。
